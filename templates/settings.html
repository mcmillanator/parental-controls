{# Annotation sections (design Screen 6) — the exact stack the mockup prescribes, shown inline (the canvas renders them visible, not collapsed). #}

Flask + Jinja + vanilla JavaScript + Bootstrap 5

No build step and no framework: server-rendered templates and POST forms. Jinja macros cover alerts, toggles, device cards, status chips and buttons.

Bootstrap is vendored locally under static/vendor/bootstrap/; product tokens, theme, focus and table-to-card rules live in static/css/app.css (the mockup's static/css/tokens.css, loaded after Bootstrap). static/js/app.js is used only for progressive enhancement (retry/toast, confirmation, reduced-motion).

Responsive Bootstrap pattern

A container-fluid with a responsive row: Notifications and Local access are col-12 col-xl-6 panels that collapse to one column below the breakpoint. Status alerts stay first and the device cards stack on small screens.

Accessibility implementation

Semantic fieldsets and legends; visible labels (never placeholder-only); keyboard focus order follows the visual order; aria-live connection status; text + icon status (never colour alone); 44px controls; reduced motion honoured; lock controls disabled while offline.
