  equivalent `patch.object(app.budgets, "X")`, which reaches through the facade

  these break if the moved code holds its own binding to the module.

**Rule the split must satisfy:** every one of these targets must still be
*effective* from where the code now lives. That is measured, not assumed:
the phase-1 gate is `RESTRUCTURE_IMPORTS.md` showing no diff **and** the
full container suite matching the recorded baseline.

## 8. The `app`-module vs `app`-Flask-instance hazard

`app.py` line 30: `app = Flask(__name__)`. Inside `app.py` the bare name
`app` means the **Flask instance**; in every other module it means the
**module**. `budgets.py` compounds it: `group_usage_minutes()` binds a
local `app` to a dict at line 1219, so `app.get("used_minutes")` in that
file is a dict lookup, not a module reference.

Consequences for the split (see RESTRUCTURE_PLAN.md §7 risk 4):
1. Concern modules must NOT do `from app import app` and also `import app` in the
   same file — pick `import app` + `app.route(...)` and one name only.
2. `budgets.py` keeps its module-level `import` set untouched; a new
   `budgets_*` module that needs a module must say `import budgets` and use
   `budgets.x` — never rebind the name `app`/`budgets` to anything else.
3. `app.py` must keep `app.py` (the filename) for `enforce_bedtime_timer`
   and `install.sh`, which both look for `app.py` next to themselves.
